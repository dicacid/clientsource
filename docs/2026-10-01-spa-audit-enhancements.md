# SPA Intelligence audit and enhancements, 1 October 2026

Target: `dicacid/clientsource`, branch `spa-intelligence-demo`, Render service
`spa-intelligence` (`srv-daukeo59fdbs739aevc0`). The B2B application's main branch
and StageTrace services were not modified.

## Observed before changes

- Render was serving commit `25a586492d7417e63ce66a521abbb42a1dabb6b9`.
- The scheduled tender scan returned a partial result with five failed direct
  sources and no new records. Public source diagnostics confirmed Queensland
  retrieval failures and HTTP 403 responses from Victoria, ACT, NSW and AusTender.
- The official Queensland datastore CSV contains 905 rows and mixed CRLF/LF
  line endings. Automatic CSV detection parsed it incorrectly. The alternative
  publisher CSV also could not be used safely because the old normalizer required
  a datastore `_id` that publisher files need not contain.
- Tender scan initiation awaited the complete pipeline in a browser request.
  Saved running scans were not continuously polled after a page reload.
- API-key setup called the public model catalogue to validate credentials.
  The live catalogue also included batch models that cannot use chat completions.
- Datastore connection helpers retained failed connection promises indefinitely.
- TypeScript checking failed, including unknown values at server-function
  serialization boundaries and stale generated route declarations.
- Render logs included 120-second SSR stream cleanup warnings. Their precise
  cause was not established.

## Implemented

- Explicit Queensland CSV delimiter and normalized line endings, validated
  schema, bounded responses, current resource metadata discovery, published CSV
  fallback and bounded CKAN pagination. Opportunity identity now survives row
  renumbering. Forward procurements retain unknown close dates and source status;
  estimated spend ranges are not treated as confirmed contract values.
- Manual tender scans return saved progress immediately and execute in the
  existing web process. Source retrieval uses at most three concurrent adapters.
  Refreshing or reopening the tender page resumes polling, and duplicate starts
  reuse the existing scan. An expired 15-minute lease becomes an explicit failed
  run. Lock release is atomic and runs even if persistence fails.
- Public source diagnostics coalesce concurrent requests and cache their result
  for five minutes. Partial source and enrichment failures remain visible.
- OpenRouter keys are checked through authenticated `GET /api/v1/key` before
  encryption and saving. Management keys are rejected. Batch and non-text models
  are excluded from the catalogue; legacy batch selections fail before research.
- Shared bounded datastore connection setup retries after initial failure and
  avoids logging credential-bearing connection details.
- Deadline normalization uses the source timezone for unqualified ISO/date-only
  values, and keeps invalid dates, invalid zones and nonexistent DST times unknown.
- Inputs and textareas use a contrasting filled surface, explicit text colour,
  larger defaults and visible focus. Native fields receive the same base styling.
- Serializable JSON types, session-result narrowing, subscription cleanup and
  array-index typing fix the existing typecheck failures. Route declarations were
  regenerated by the build, not edited manually. A lockfile and CI typecheck now
  make dependency resolution and validation repeatable.

## Validation before deployment

- 39 automated tests passed.
- Production build and TypeScript check passed.
- The new adapter retrieved the live official Queensland dataset from the test
  environment: 905 total rows, 21 relevant forward procurements.
- A real isolated Redis integration check verified immediate background start,
  duplicate-run protection, partial failure status, persistence, deduplication,
  preserved notes/workflow, deadline-change audit, lock release and stale recovery.
- Local production HTTP checks returned 200 for sign-in, health and protected
  route shells; unauthorized cron invocation returned 401. Route-shell checks do
  not establish an authenticated workflow or AI execution.

## Operational boundaries

The background scan runs in the existing web service, not a durable worker.
Deployments or process exits can interrupt a run; stale recovery allows a retry.
The existing state mutation queues are process-local, so this change does not
claim safe horizontal scaling. No datastore migration or Supabase was added.

An authenticated production session and an authorized AI request were not
available in the audit browser. AI validation tests used controlled responses.
Direct portal availability and production ingestion must be checked after deploy;
HTTP 403 coverage gaps cannot be claimed fixed by parser changes.
